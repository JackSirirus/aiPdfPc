规格说明 · S1

状态与行为
  • 对话框 880 × 560，覆盖应用；Esc / ✕ / 取消 关闭不保存。
  • 左列搜索按显示名 / provider id 过滤；输入无匹配显示空态。
  • 切供应商保留各自已填内容；未保存时点「取消」丢弃改动。
  • 「测试连接」结果就地显示：已连接 / 密钥无效 / 网络不可达 / 超时，不改动已保存的状态点。
  • 「撤销同意」清除该 服务商 + endpoint 的同意记录，不动其他组合。
  • 保存后写入 settings；密钥另走入凭据管理器，不随 settings 落盘。
  • 「测试连接 / 拉取模型」均为用户显式触发；云端会发送密钥但不发送文档内容；不替代文档上传同意。
字段与默认值
  • 供应商：默认 OpenAI（首次启动预选首个内置供应商）。
  • API Key：掩码回显，空 = 未配置；「保存到凭据管理器」显式提交。
  • 模型：来自该 provider 的预设列表，默认取其第一个（OpenAI = gpt-4o）。
  • 端点：内置默认 base URL，可覆盖；变更需重新同意。
  • 同意记录：存 provider + endpoint + 密钥指纹 + 时间 + TTL，不存密钥与正文。
S2 · 设置页 · 本地服务

规格说明 · S2

状态与行为
  • 「拉取模型」调用 GET {base}/v1/models；成功列出模型，失败显示分类错误（不可达 / 401 / 404 / 超时）。
  • 拉取成功才启用模型下拉；未拉取时下拉禁用并提示先拉取。
  • 地址变更后旧模型列表失效（须重新拉取），避免选到不存在模型。
  • loopback 判定基于解析后的主机，不信任字符串前缀（127.0.0.1.evil.com 不算本机）。
  • 不探测端口、不自动改地址、不自动重试拉取。
字段与默认值
  • API 地址：默认 http://127.0.0.1:11434/v1（Ollama）。
  • 端口 chips：11434 Ollama / 1234 LM Studio / 8000 vLLM / 8080 llama.cpp。
  • 模型：来自拉取结果，默认选中第一个（示例 qwen2.5:7b）。
  • API Key：默认空（不带鉴权头）。
  • 同意：本地 loopback 不产生同意记录；非 loopback 按云端规则。

规格说明 · S4

状态与行为
  • 折叠态只显示 供应商 · 名称 · 模型；点击「更换 ▾」就地展开，不改变抽屉宽度。
  • 同一时刻只展开一个块；点「完成」或切换 Tab 收起。
  • 展开期间可正常滚动与修改其他配置行。
  • 切到未配置供应商 → 内联提示 + 禁用「开始整篇翻译」。
  • 切到云端新组合 → 首次调用仍走同意流程（S1 的逻辑不变）。
字段与默认值
  • 摘要行：供应商名 + 模型名，默认取上次使用者。
  • 快捷项：供应商 / API Key / 模型 / 拉取·测试 / 完成。
  • 状态点语义与设置页一致（绿 / 灰）。
  • 展开块高度自适应，不撑破 320px 抽屉宽度。

规格说明 · S7

状态与行为
  • 编程套餐端点不默认选中：内置预设默认走标准 API，套餐端点须在「协议 / 端点」处显式选择。
  • 选中套餐端点后合规警示常驻详情页顶部，重开设置不消失、不可永久关闭。
  • 协议按模型覆盖：modelProtocols 命中即覆盖 provider 级 apiProtocol（opencode go 混合协议）。
  • 「改用标准 API」一键把端点切回该供应商标准 base（GLM → open.bigmodel.cn/api/paas/v4），并清除套餐端点的同意记录。
  • 套餐端点配到非套餐 Key 时，错误分类提示「该 Key 不适用于订阅端点」，不误导为网络错误。
字段与默认值
  • apiProtocol：provider 级，取值 openai | anthropic；默认 openai（Anthropic / 编程套餐默认 anthropic）。
  • modelProtocols：按模型覆盖表，命中即覆盖 apiProtocol。
  • coding 套餐 Key 与标准 Key 不通用：sk-kimi- 仅 Code 端点；GLM 套餐仅 glm-5.3 / glm-5.3-flash。
  • 端点：标准 API 为默认值，套餐端点为可选覆写值（GLM 海外 api.z.ai/api/coding/paas/v4 / api.z.ai/api/anthropic）。
  • 协议只决定请求路径（/chat/completions vs /messages），不改变 base URL。
  • ① 合规警示常驻，不是一次性弹窗：只要当前端点是订阅 / 编程套餐，详情页顶部即显示警示条；文案与「改用标准 API」按钮固定，用户无法永久关闭。
  • ② 默认走标准 API：内置预设的默认端点始终是标准 API；编程套餐端点必须由用户显式选择，避免误用导致不计额度（GLM 返回 1113 Insufficient Balance）。
  • ③ 协议维度：apiProtocol 为 provider 级默认，modelProtocols 可按模型覆盖；opencode go 同时含 OpenAI Chat Completions、Anthropic Messages、OpenAI Responses 三类模型，因此呈现为「混合（按模型）」。
  • ④ Anthropic 协议适配落在 Python 引擎：Anthropic Messages 与 OpenAI Chat Completions 的请求 / 响应结构不同，适配层将在 backend/translate/llm.py 实现；本设计稿只约定字段与默认值，不含实现。
  • ⑤ 环境变量沿用既有约定：OPENCODE_API_KEY 等仅作「在环境变量里找 Key」的命名约定；密钥仍只存系统凭据管理器，仅经 stdin 传递。
