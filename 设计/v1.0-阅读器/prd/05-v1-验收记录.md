## 2. 预算实测

**P95 口径**：对 n 个 `Stopwatch` 样本升序排序后取第 `ceil(0.95*n)-1` 个（0 基）。P95 与样本数 n 逐项标注。
**语料**：`tmp/t2-corpus/corpus/t2-cjk500.pdf`（500 页中英混合文本层，合成文件，`tmp/` 不入库）。B3 用 `tmp/pdfium-spike/corpus/text1000.pdf`（1000 页）。
**应用层口径**：经真实服务 API（含后台线程/锁/LRU 等应用层开销），与 spike 的 binding 层裸调用数值不可直接对齐。

| 指标 | 定义（本次方法） | 目标 | 实测 | 样本 | 判定 |
|---|---|---|---|---|---|
| **B1** 单页渲染 96dpi | 文档句柄已打开、页尺寸已解析（热文档）；每次渲染**不同页**以测真实渲染（非位图 LRU 命中）；`RenderPageAsync(page, 96, 100)` | < 200 ms | **P95 3.09 ms**（min/median/max = 1.40/2.12/3.32） | n=30 | **PASS**（-98%） |
| B1 附：位图 LRU 命中 | 同一页重复渲染（缓存命中路径） | 参考 | P95 0.00 ms | n=30 | 参考 |
| **B2** 单页渲染 150dpi | 同 B1，dpi=150 | < 200 ms | **P95 6.99 ms**（min/median/max = 3.07/4.36/8.95） | n=30 | **PASS**（-97%） |
| **B3** 千页文档打开 | `OpenDocument(text1000.pdf)`：读入字节 + `FPDF_LoadMemDocument64` + 逐页解析 1000 个页尺寸；**不含**进程启动/JIT/首页渲染 | < 3 s（预算表完整冷启动口径） | **中位数 144.6 ms**（range 136.2–145.3） | n=3 | 记录（应用层打开口径；完整冷启动未测） |
| **B5** 全文搜索 | 500 页文档，首次搜索建全量索引后，重复搜索同一词（含 500 处命中矩形换算）；排除首次索引 | < 500 ms | **P95 69.62 ms**（min/median/max = 45.89/51.58/70.52）；首次索引构建 124.6 ms（一次性） | n=30 | **PASS**（-86%） |
| **B9** 256MB 缓存驻页 | 默认 256 MB 字节预算，顺序渲染 200 页后统计驻留页数/字节；再回访驻留窗口测命中 | ≥ 50 页 | **驻页 75 页**（254.8 MB）；回访最近 75 页命中 **75/75 = 100%**；顺序扫描命中率 0%（LRU 顺序访问的固有行为，非缺陷） | 200+75 次 | **PASS** |

**备注**：
- B1/B2 在报告前多次运行中出现 3–15 ms 波动（首次 JIT/预热影响），均远优于 200 ms；本表取最后一轮完整 harness 运行（11:14:57 采集）的落盘值。
- B3 与 `03-验收预算表.md` 指标 3 的 binding 层 2.84 ms 不是同一口径：本值含读盘 + 1000 次页尺寸原生解析，故量级更高；应用层打开 < 200 ms 不影响「打开即读」体验。
- B9 的顺序访问命中率为 0 是 LRU 在顺序扫描下的确定性结果；回访最近窗口（真实阅读的翻回/缩略图回收模式）命中率 100%。

**3.3 回归覆盖层级（诚实标注）**

| 层级 | 覆盖 | 说明 |
|---|---|---|

**3.4 回归中的一处测试隔离坑（非生产缺陷）**

`EditorPages.Register()` 带 `_registered` 幂等守卫，而测试会在 `ToolPageRegistry.Reset()` 后重新注册；当其他测试先注册过编辑组时，守卫令 `Register()` 变 no-op，导致 Reset 后编辑组解析器缺失（表现为 `rotate` 等工具 `TryCreate` 返回 null）。这是**测试隔离问题**，生产只在 MainWindow 启动时注册一次、不 Reset，行为正确。临时 harness 已通过反射清零该守卫验证 32/32；正式测试套件未包含该断言（保持基线 357），结果仅落证据与本节。

## 4. 单栈评估（PDFtoImage / PdfPreviewControl）

**结论：双栈并存，保留 PDFtoImage，不在 V1 删除；V2/V3 收敛。**

`grep` 全仓 `PdftoImage|PDFtoImage|PdfPreviewControl|PdfPreviewDocument` 结果：

| 归属 | 使用点 | 性质 |
|---|---|---|
| 生产（工具页） | `Views/Editor/CropPage.xaml`、`EditPage.xaml`、`FormsPage.xaml` 内嵌 `<controls:PdfPreviewControl>` | **仍在使用**，裁剪/编辑/表单依赖旧栈的框选预览 |
| 生产（控件层） | `Controls/PdfPreviewControl.xaml(.cs)` → `PdfPreviewDocument` → `PDFtoImage` | 旧预览栈本体 |
| 阅读器（新栈） | `Rendering/PdfiumRenderService` + `Views/Reader/*` 用 PDFiumCore | V1 新栈，与旧栈互不依赖 |
| 测试 | `PdfLoadTests` / `ConverterTests` / `EditorTests` / `WorkflowTests` 使用 `PdfPreviewDocument` 校验产物 | 测试依赖 |
| 其他 | `App.xaml` 注释、`PdfCoordinateMapper` 注释、`EditorViewModels` 注释 | 文档性引用 |

- 旧预览控件仍有**生产调用方**（crop/edit/forms），故按任务约定**不删除**，记录为「双栈并存，V2/V3 收敛（`04-阅读器PRD.md` 4.1 决策 18 的单栈原则待这些工具页迁移到 PDFiumCore 后达成）」。移除 `PDFtoImage` 引用**不在本任务范围**。

## 7. 已知问题与环境阻塞

### 7.1 环境阻塞（本次无法执行，如实标注）

1. **真实 UI 点击验收未执行**：当前环境无可交互 WPF 桌面，无法「启动 exe → 打开文档 → 滚动/缩放/搜索/多工具处理」并截图。计划中的 T3/T4/T5/T8 界面 QA 截图同样缺失。**统一交 F3 真实操作 QA 波次**。
2. **dist exe 启动冒烟未执行**：无法启动 GUI；改由 build.ps1 的 dist 引擎 health 冒烟（`vision=true`）覆盖运行时可用性，不等价于 GUI 冒烟。
3. **逐工具真实处理未执行**：32 工具在本环境仅验证到「路由 + 页面创建」；「处理并产出结果文件」需 UIA 驱动对话框 + 引擎进程，交 F3 与既有引擎集成测试。

### 7.2 已知问题（记录，不隐瞒）

1. **Smart App Control 拦截未签名原生库**：本机 SAC 评估态按文件哈希/云信誉放行，`bblanchon.PDFium.Win32` 154.0.8035 被拦（`0x800711C7`/WinError 4551），并会击穿旧 PDFtoImage 栈。故 PDFiumCore 与原生**钉 152.0.7961**（与 PDFtoImage 原生依赖一致、有既往信誉）。154 提升需原生哈希获得信誉或维护者调整本机策略（单向操作）。
2. **双文档句柄**：T1 渲染服务与 T2 文本服务各持一份固定字节与文档句柄，未共享（V1 取舍）。
3. **渲染 API 缺口**：`RenderPageAsync` 无 `CancellationToken`；无显式 `ReleasePage`（靠 LRU 预算淘汰）；无渲染优先级队列。均以 V1 适配层兜底（规格戳丢弃过期结果、视图侧置空触发释放、占位态兜底快滚）。
4. **B9 顺序访问命中率 0%**：LRU 顺序扫描的固有行为（回访窗口 100%），非缺陷，记录以免误读。
5. **测量波动**：B1/B2 受 JIT 与后台负载影响，单次 P95 在 3–15 ms 间波动，均远优于目标；正式回归若引入性能断言建议放宽阈值。
